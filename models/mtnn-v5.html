02

What it predicts

Given one player-season's stat profile, MTNN v5 answers a single question: which other player-seasons play the game most like this one? It compresses each season into a 64-d unit vector and ranks neighbors by cosine similarity. Daily Court, Twin Networks, era twins and the dossier twin-reveal run on this space. Career trails are drawn in the map's PCA projection of the 14 era-normalized stats.

The honest test: given season N, can it find the same player's season N+1 among all 12,966 seasons? (We call this held-out adjacent-season retrieval.) Splits: train ≤2021, val 2022–23, test ≥2024.

The baseline is the transparent 14 era-z features (vectors.json, cosine). MTNN beats it roughly six-fold on the test split. The adopted run claims test recall@10 of 0.846 and archetype accuracy of 0.970, but those were recorded before the holdout — trust the table above, not the claim.

Secondary outputs from the lineage: archetype classification (top-1 accuracy 0.970) and purity@20 of 0.783 — nearest neighbors land in the same archetype family about four times in five.

03

In plain words

Take every NBA season from 1996 to today. Turn each one into a 64-number fingerprint that captures how a player scored, passed, rebounded, defended, and shot — adjusted so a 1998 season can fairly meet a 2025 one. Seasons with similar fingerprints sit near each other. That's it. The games on this site are different ways of walking around that neighborhood: guessing twins, drawing networks, comparing eras.

The fingerprint gets it right a lot more than the simple version does — on genuinely unseen seasons it finds the right player's next season 44% of the time versus 8% for the simple stat table — but it's weaker on modern seasons, blind to anything not in the box score, and it never tells you who was better, only whose game looked alike.

04

What it cannot do

  • It cannot say who was better. It ranks similarity, not greatness. A twin match means "played the game the same way", never "was as good as".
  • It cannot predict the future. Forecasting (Arc Forecaster, TimesFM lanes) is a different model family; similarity is not a projection.
  • It cannot see defense fully. Defense enters through the stat-derived defense family (steals, blocks, rebounds); there is no tracking data before 2013, and none of it captures scheme or effort.
  • It cannot judge context. Injuries, load management, tanking rosters, and playoff-only gears are not in the input; the vector describes what happened in the box score, era-normalized.
  • It cannot compare eras absolutely. Features are z-scored within each season, so cross-era twins are era-honest by construction — a 1998 season and a 2024 season match on relative profile, not on pace or absolute scoring.
  • It cannot score below the eligibility floor. Seasons under the schedule-aware minutes/games floor aren't queryable twins; ambiguous name-in-season rows (3 of 12,966) are excluded, never guessed.
05

Known biases

Era bias — weaker in the modern game
Test-split retrieval top-1 is 61.6% for 1996–99 queries but 38.5% for 2020s queries. Similarity is less certain in the modern game, where roles and shot mixes have converged.
Train-heavy evaluation
8,553 of the 10,104 evaluated pairs come from the train split, where the queried pairs were InfoNCE positives during training. The test split (790 pairs) is the honest number.
Box-score worldview
Everything the model "knows" is a stat line. Playmakers whose value is spacing, screening, or defensive communication are systematically under-described.
Final-season and short-career gaps
491 final charted seasons can't have a next-season pair, and one-season careers are the model's least-measured territory.
Provenance gap
The model's training run is not reproducible from the repo: no checkpoint, no train git SHA, no run report. The champion is verified byte-for-byte, but its birth certificate is missing — see registry & lineage.
06

Registry & lineage

This model is tracked in the versioned registry: models/registry.json — id mtnn-v5, status champion, data window, metrics, artifact paths, and provenance, all machine-readable. The registry's champion entry is checked against the served bytes by CI's served-model gate: if the registry and the served bundle ever disagree about the run id or the file fingerprint, the build fails.

The gate's current state is red: the lineage was reconstructed from the served bytes (git blob a4918f09) because the original July 2026 run directory is not in the repo. Export floors were waived by --force; the checkpoint, train git SHA, and run report are unknown. Resolving it takes one of two things — find the original run files, or order a deliberate replacement champion — and both are the owner's decision. The full accounting is in models/lineage-gate.md.
