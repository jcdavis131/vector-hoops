3 · 64-d dimension contributions — dimensions, NOT towers

Each bar = embCurry[i] × embGinobili[i]. They sum to the 0.4003 dot product. Dimension indices have no basketball name — claiming dim 43 “is shooting” would be invented. Honesty box — what is measured, estimated, or unavailable

  • Measured: all 64-d and 14-d cosines/ranks (full 12,966-row exhaustive ranking, person-excluded); dimension decomposition (exact arithmetic on served embeddings); 14-d group/LOSO ablations (real re-ranking); facet values (read directly from vectors.json / skills.json); counterfactual ranks (real re-ranking of the moved vector).
  • Estimated-from-facets (never model internals): any talk of “towers” on this page. The 17 tower families are named in the contract, but no tower score is computed from the served model here.
  • Unavailable (explicit gap): true served-model tower ablation — the 120-feature input matrix is uncommitted, so v5 cannot be re-run with a tower masked. That node is drawn red and dashed, not papered over.
  • Banned, never used: mtnn.onnx (119→48, not the served 64-d), mtnn_attr_pop.json and mtnn_jacobian.json (48-d pre-v5 exports marked not_from_served_net). Presenting any of them as v5 attributions would be false.
  • Skills coverage: skills.json grades 12 skills per row. mtnn_meta.json lists 18 skill keys, but post, transition, motor, shooting_gravity, rim_gravity and disruption_gravity have no per-row grades in skills.json, so they are not shown as facets.
  • Reproduce: python3 precompute.py regenerates data.json from the read-only assets; this page embeds that same JSON (see NOTES.md for the inject command). No server, no external fetch, no new package.

Prototype only. No training run, no GPU, no write to any repo checkout, no merge. The coordinator — not this page — presents both prototypes; the user judges.
