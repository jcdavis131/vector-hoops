🏀 Forecast Attribution

Question: for one player's predicted next-season line, which past signals drive it? Click a signal below and watch the predicted line move. Every number on this page was computed by precompute.py from the real 12,966-row dataset — nothing here is hand-written.

Read this first — what this is, and is not.
  • Prediction-first framing: user-directed, pending panel ratification (CONTRACT §11 HOLD). This prototype drafts the idea; it does not finalize the spec.
  • These are labeled BASELINES, not model predictions. The forecast is a neighbor baseline (K = 25 similar past player-seasons; their actual next seasons, averaged). It is not the v5 model talking.
  • The v5 next-profile head is NOT runnable from saved assets. mtnn_heads.f32 holds only saved per-row outputs (12,966 × 45), no weights, no documented column layout, no checkpoint file in assets/. Its last 14 columns are a shrunk copy of the current season, not a usable forecast (MAE vs actual next season 0.4708 vs carry-forward 0.4732). So no model-internal attribution is shown — see Gaps below.
  • Units: every stat is a season-relative z-score (+1.0 = one standard deviation above that season's average). The dataset stores z-scores, not raw per-100 values, so no raw line is invented.
  • Honest headline: across 9,787 past cases the neighbor baseline (MAE ) does not beat carry-forward (MAE ). This demo proves the attribution mechanics — remove a signal, the line moves by a measured amount — not forecast skill.

4 · Why the full forecast looks like this

The forecast is the average of the actual next-season lines of the 25 most similar earlier player-seasons (same person excluded, keyed by person_id). Change the inputs, the neighbors change, the forecast changes — that is the whole causal chain, and it is measurable above.

Gaps — stated plainly

  • No tower-level or gradient-level model attribution. True served-v5 tower ablation is unavailable in this pass (120/130/143-feature input matrix not on disk; saved mtnn.onnx is a stale 119→48 export, and mtnn_attr_pop.json / mtnn_jacobian.json are 48-d pre-v5 exports marked not_from_served_net). None of those are used here.
  • SAE / JEPA attributions are v1 notes only — no such attribution is faked as working anywhere on this page.
  • Team context is a proxy. No separate team field is used; FTA + PLUS_MINUS is the closest stored proxy, and it is labeled as such.
  • Stored workload fields (games, total minutes) are used as stored in vectors.json; they are not re-derived into real minutes per game.

Method detail: distance = Euclidean over 17 standardized dims, equal weight (14 game-vector z-scores + age_z + gp_z + total_min_z). Candidates: earlier seasons only, own next season known, same person_id excluded. Reproduce everything with python3 precompute.py in this directory (inputs read-only; only data.json is written).
