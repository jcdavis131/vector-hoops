loudly below 50% coverage.

**Defaults.** All 8 fields of the zero-recall run matched argparse defaults
(`tower 24/96`, `blocks 1`, `fusion gated`, `nce infonce`, `lr legacy-epoch-cosine`,
`epochs 40`). Defaults are now the measured winner; verified a bare invocation
reproduces the explicit recipe exactly (test 0.838, CQS 74.15).

**`FORM_GP`.** `3306bf6` retired `CAREER_GP_PCT`/`MISS_STREAK`/`AVAIL_3Y` for
feeding the durability head its own label and **missed `FORM_GP`** (r = +0.9676

## The promote gate

Was `{"cqs": 85.87, "recall": 1.0, "purity": 0.8726}` — seeded 2026-07-09 from
the pre-protocol loop that trained on held-out positives. `MTNN_V5_PROMOTE_GATE.md`
already documented that `recall@10 = 1.0` as memorization, so the rule
`recall >= baseline - 0.02` demanded **≥ 0.98** against a best honest measurement
of 0.768. It rejected every candidate silently.

Now:

* `BASELINE` = CQS **75.62** / recall **0.742** / purity **0.7822** /
  continuity_spread **0.119**, measured over **6 seeds** on the 130-feature matrix.
* `BASELINE_SD` = 2.44 / 0.128 / 0.0064 / 0.083 — thresholds derive from these,
  not hand-picked. Effective slack is **2× the standard error of the seed mean**,
  so one seed must clear +3.22 CQS while four seeds tightens to +1.61. The old
  flat 0.02 slack sat ~4× *below* real noise on test recall.
* `BASELINE_PROVENANCE` records recipe, seeds, protocol and matrix. **Read it
  before touching the constants.**
* New **continuity-spread guard** catches the failure that actually shipped
  (strong val, test → 0, same-player continuity collapsing outside the training
  window).

### Re-anchoring rule (important)

Anything that changes `train_matrix.npz` — retiring a feature, adding a family,
changing normalization — **moves the matrix the baseline was measured on**.
Re-measure `BASELINE` and update `BASELINE_SD` + `BASELINE_PROVENANCE` in the
*same commit*. That is exactly what `45ce92d` → `7e1d28b` did.

```bash
python pipeline/sweep_stability.py --arms long --seeds 5,7,13,21,42,99 --out baseline_reanchor.json
```

### Known wrinkle: seed 42

Five of six seeds cluster in **76.33–77.25 (sd ≈ 0.37)**. Seed 42 is a bad basin:
CQS 70.69, test 0.484, continuity spread 0.2876. It is **kept in the mean, not
trimmed** — roughly 1 run in 6 lands there, and a baseline hiding that would
understate the evidence a promotion needs. Verified the continuity guard still
rejects a seed-42-like model with the outlier included. Worth investigating
whether it is initialization or a data-order interaction.

## Hill-climb results — nothing beat noise

Accept bar +1.2 CQS (≈ noise on a 2-seed mean). Nothing cleared it.

| climb | best arm | Δ CQS |
|---|---|---|
| family inputs (6/18 arms) | `drop_efficiency` | +0.86 |
| individual features | drop `FORM_GP` + `DRAFT_NUMBER` | +0.06 |
| capacity | `concat dim64` | +0.82 |
| fusion | `concat 256 d64` | +0.82 |

Two findings worth keeping:

1. **`gated` fusion is unstable, not merely weak** — per-seed CQS 61.09 vs 43.55.
   It is the wrong fusion at every width tried. `concat` 32/160/2 remains the
   recipe.
2. **CQS may be mis-weighted for the product.** `transformer` has the best test
   recall (0.841) *and* the flattest continuity (0.0676) — the best generalization
   profile in the sweep — yet ranks 7th of 8 on CQS, because purity 0.16 +
   archetype 0.08 outweigh recall 0.18. **The game ranks by cosine retrieval, not
   cluster purity.** Flagged deliberately, not changed: this is a product call.

## New tooling

| file | purpose |
|---|---|
| `pipeline/audit_features.py` | Input-matrix audit: dead/near-constant columns, duplicate pairs, leak candidates vs head targets, coverage cliffs. Read-only. How both remaining data bugs were found. |
| `pipeline/sweep_stability.py` | Config sweep scored on **same-player continuity** as well as recall. Continuity localized the collapse in one number (0.182 vs 0.785) where recall alone hid it. Snapshots each arm's report + embedding. |
| `pipeline/hill_climb.py` | Greedy multi-seed climber over family inputs (`--mode families`) and fusion (`--mode fusion`). Accepts a step only when the gain clears the noise floor **and** every seed agrees on the sign. |
| `pipeline/test_composite_gate.py` | 15 tests pinning the gate. Load-bearing one fails if `BASELINE['recall']` ever returns to 1.0. |
| `pipeline/test_feature_hygiene.py` | Turns the whole bug class into an exit code: retired features stay retired, no dead columns, no new input duplicates, no input within r=0.95 of the durability target. |
| `train_mtnn.py --mask-features` | Per-column sibling of `--mask-families`. Test a single feature **without** rebuilding the matrix (which would invalidate the baseline). |
| `train_mtnn.py` `vector_head_report()` | Scores multi-target heads. `regression_head_report` was single-target only, which is why durability went unmeasured. |

Both gate scripts are wired into `update_dataset.py` as required steps and are
matrix-only (no training, cheap).

## Deliberate non-actions

* **`DRAFT_NUMBER` ~ `DRAFT_SLOT_Z` (r = +1.0000) left in place.** The identical
  number sits in two towers, but masking it measured free (CQS +0.00) and removing

* **`FORM_GP` still produced** by `form_context.py` / `build_vectors.py`.
  `RETIRED_FEATURES` drops it at merge; the hygiene gate asserts its absence from
  the matrix. Removing the producer is churn with no gain.
* **`assets/mtnn_attr_pop.json` still references `FORM_GP`** — it describes the
  *deployed* 131-feature model, which is unchanged, so it is correct as-is. It
  must be regenerated whenever a model trained on the 130-feature matrix is
  promoted.
* **A previous draft of the stability doc claimed three rival recipes.** That was
  wrong and is corrected in §1a: `rebuild_all.py`'s production path already matched
  the good recipe flag-for-flag, and its transformer variant is behind an opt-in
  `--v6`. The argparse defaults were the only rogue recipe.

## The lesson worth carrying

Four hill-climbs over inputs, features, capacity and fusion moved nothing. Four
plumbing bugs moved everything — and all four were invisible in the loss curve:
a head with no labels, a stale artifact, a default config, a leaked input. Two of
them were *weighted heads training on nothing*.

**Audit the plumbing before tuning.** `audit_features.py` and
`test_feature_hygiene.py` exist so the next one shows up as an exit code instead
of a quiet regression.
