# docs/launch — the trust layer

The Trust & launch kit for the Vector Hoops product platform (Pillar 8).
Five documents, one discipline: fast, correct, explained, shareable.

| Doc | What it is |
|---|---|
| [launch-checklist.md](launch-checklist.md) | The per-surface launch checklist — the four bars (FAST · CORRECT · EXPLAINED · SHAREABLE), sign-off, and the #126 pre-launch audit as the worked example. |
| [provenance-ledger.md](provenance-ledger.md) | The ledger format: every number traceable to source + vintage. Field schema, status rules, real worked rows, the drift changelog. |
| [methodology-outline.md](methodology-outline.md) | The dumbmodel.com methodology content outline — how the nets work, what embeddings mean. Content only: no code, no deploy. Includes the edge-decay open decision. |
| [security-review.md](security-review.md) | The pre-launch security ritual — five lanes (secrets, PII, injection, reputation, config), step-by-step, verdict template, the CSP report-only standing item. |
| [feedback-triage.md](feedback-triage.md) | The user-feedback format — report → triage → fix → changelog, with the severity guide and the 11-item fix-list worked pattern. |

The binding rules these docs serve: real data only (unknown = "unknown",
never invented); honest 503 over fake success; hard-block on data QA
failure; every number recomputable from source; no merge without his word.
