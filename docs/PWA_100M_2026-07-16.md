## Strategies

1. **HTML navigations: network-first + offline fallback**
   - Try `event.preloadResponse` (navigationPreload enabled in activate)
   - Then network fetch, cache clone on 200
   - Catch → cache.match(req) → offline.html → '/' fallback
   - Ensures fresh Daily puzzle # when online, offline still works.

2. **Immutable core (exact CORE pathname): cache-first with background update**
   - Return cached immediately if present → TTI <300ms second load
   - `event.waitUntil(fetch+put)` updates in background
   - If no cache, await network, cache and return
   - Guarantees instant offline after first install

3. **Other assets (/assets/*.js .css .json .png .webp): stale-while-revalidate**
   - cache.match → return cached if present while fetching update (cl <4MB guard)
   - If no cached → await network
   - Avoids quota blow, keeps Lab assets fresh-ish

4. **Denied huge files: network-only, no put**
   - `DENY_CACHE` array check `url.pathname.includes(deny)` → fetch only, 504 on fail, never cache
   - Prevents 8.7M file killing storage on low-end

5. **Default: cache-then-network**

Other:
- Only GET, same-origin only
- `skipWaiting()` install + `clients.claim()` activate + `navigationPreload.enable()` for 100M DAU fast swap
- `content-length` guard <4M in SWR put
- Message handler `SKIP_WAITING` for update toast flow

## Update Flow

- index.html + play.html both register `/sw.js` scope '/'
- Toast div `#vh-update-toast` fixed bottom 12px + safe-area, dark ink bg #1A150F, yellow button #F0E442, hidden by default
- Logic:
  ```
  register().then(reg=>{
    if(reg.waiting) showToast(reg)
    reg.updatefound → nw.state installed && controller → showToast
  })
  toast button → waiting.postMessage({type:'SKIP_WAITING'}) || location.reload()
  controllerchange → reload once
  ```
- Avoids breaking mid-game: toast only appears after install, user taps Update →
- Version string v8-20260717 visible in nav badge on offline.html for debugging
